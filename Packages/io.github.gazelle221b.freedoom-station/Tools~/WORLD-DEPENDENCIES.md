Lighting packages are installed with Unity's Package Manager API. Reinstall the same pins with `Tools > New World > Install Lighting Packages`.

The LTCGI integration requires VRCLightVolumes 3.0.0-dev.1 or later (https://ltcgi.dev/Advanced/VRC_Light_Volumes). After authorization to include dependencies, the project uses pinned LightVolumes 3.0.0-dev.20 and LTCGI 1.7.3. This enables the bridge types and scripting definition. LightVolumes is a development release. All scene files were backed up before the update; existing scenes contain no old LightVolumes script references.

## Scene use

Packages and source assets are available without changing the world's layout. Add the LightVolume manager/volumes and LTCGI Controller/emitters when lighting is designed. Follow the upstream setup and bake instructions. Include LTCGI attribution when using it in a published world: https://ltcgi.dev/Getting%20Started/Installation/Attribution.

rvc is PiMaker's RISC-V shader emulator. Its upstream repository provides assets, not a ready-made terminal prefab. Imported source assets are under `Assets/ThirdParty/PiMaker/rvc`; upstream README and MIT license are included there. Large upstream demo payload/state PNGs are omitted and the sample VM's 13 texture bindings are empty. The separate DoomStation uses locally generated textures; follow `Tools/Doom/README.md` to build and import them.

## rvc compatibility changes

- Preserve upstream asset GUIDs, shader include paths and generated headers. Demo program textures are supplied locally rather than committed.
- Import the official Dial's scripts, prefab, FBX meshes, material, texture, and sound under `Assets/ThirdParty/PiMaker/Dial`. Restore NixControl's original Dial field type. Change Dial.SetState's visibility from private to public for rvc's existing boot transition. The standalone `RvcRunSwitch` remains available as a simple alternative.
- Supply a queued UART `KeyboardManager2` with an optional InputField. Wire its `vm_mat` to the VM material, and `Debug` to the NixDebug UdonBehaviour. Wire InputField submission to the `Submit` custom event.
- Replace framebuffer control-character literals with equivalent ASCII integers for Unity 2022's shader compiler.
- `Tools > New World > Repair and Compile rvc` removes unused serialized texture properties and recompiles UdonSharp program assets using Editor APIs.
- Keep optional upstream `AutoImport.cs` and `ExportState.cs` in `Tools/ThirdParty/rvc-source-tools`, outside compiled Assets. AutoImport assumes the author's local Perl layout and hard-coded `Assets/_Nix` path. Existing generated shader headers do not require Perl. These originals are references, not active scripts.
- Do not copy the orphan `main.o.meta`.

For a terminal, build and wire the CRT, display/debug cameras, UI, NixControl, NixDebug, NixProgramLoader, and keyboard/run controls according to upstream. Test Linux boot separately. Package import and a world Play smoke test do not prove that an unwired emulator can boot.

`Tools > New World > Repair Official Dial References` recompiles the three Dial programs, repairs label fonts with Unity's built-in font, reconnects missing collider meshes to the same object's FBX visual mesh, and updates the prefab's bytecode references. Original Dial.cs and source hashes are preserved under `Tools/ThirdParty/Dial-source`. Dial is CC BY-NC-SA 2.0; preserve PiMaker attribution and the included license. Upstream asks users to contact the author for commercial use. rvc itself remains MIT.

`Tools > New World > Validate Imported Packages` checks shader errors, compiles Udon for both the VRChat client and Editor, checks imported program assets and GUID references, and confirms the LTCGI LightVolumes bridge type. Package authoring extensions for Amplify Shader Editor, VRCFury and Modular Avatar are reported as optional references; they are outside this world runtime. Generated bytecode and controller/bake-bound textures are reported separately from missing required references. Existing UdonSharp, uGUI, TextMeshPro, and Editor Coroutines satisfy the runtime/editor prerequisites. Payload-rebuilding Linux/Perl toolchains and the optional CyanEmu simulator are not required; ClientSim is already available.

Installer, repair, and validation helpers are Editor-only and run only from their menus or explicit request files under Library.
